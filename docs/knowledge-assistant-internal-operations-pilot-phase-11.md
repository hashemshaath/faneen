# Knowledge Assistant — Internal Operations Pilot (Phase 11)

## هدف التشغيل الداخلي
تشغيل المساعد المعتمد على `knowledgeRegistry` داخليًا لمدة أسبوع لقياس الجودة على أسئلة حقيقية، دون أي تفعيل عام، ودون إرسال أو حفظ، قبل التفكير في التوسع.

## من يستخدمه
- الأدمن (`admin`).
- فريق التشغيل (`operations`).
- فريق الدعم (لأغراض صياغة المسودات فقط).

## أين يستخدم
- داخل `/admin/knowledge` فقط.
- Tabs المسموحة: `اختبار المساعد`، `ردود الدعم`، `جودة المساعد`.
- ممنوع استخدامه في: داشبورد العملاء/المزودين، الموقع العام، البريد، واتساب، التذاكر التلقائية.

## مسموح
- اختبار أسئلة العملاء والمزودين داخل الـ Preview.
- توليد مسودات ردود دعم.
- نسخ الرد يدويًا **بعد مراجعة بشرية**.
- استخدام المصادر للتحقق من صحة الإجابة.

## ممنوع
- إرسال رد تلقائي عبر أي قناة.
- حفظ المحادثة في قاعدة البيانات.
- إدخال بيانات شخصية حساسة في حقل السؤال.
- السؤال عن أرقام جوالات أو بيانات تواصل مزودين.
- طلب «أفضل مزود» أو ترشيح.
- إعطاء سعر تقديري أو ضمان تنفيذ.
- مشاركة محتوى `internal` مع عميل أو مزود.

## متى نستخدم fallback
عندما يعرض المساعد رسالة: «لا توجد معلومة موثقة كافية…» — لا تخترع إجابة، وسجّل السؤال في الجدول أدناه بنتيجة `fallback` أو `needs_knowledge_update`.

## متى نصعّد للدعم
- شكوى، نزاع، استرداد مالي.
- طلب تعديل عقد أو بيانات حساب.
- أي سؤال يتطلب قرارًا بشريًا (انظر `escalationTopics` في `knowledgeAssistantReleaseGate.ts`).

## كيف نسجل السؤال يدويًا
استخدم الجدول أدناه. سجل صفًا واحدًا لكل اختبار، ثم اجمع النواقص في نهاية الأسبوع.

## كيف نقرر إضافة محتوى معرفة جديد
- إذا تكرر `fallback` لنفس السؤال ≥ 3 مرات داخل النطاق، أنشئ عنصر معرفة جديد عبر `/admin/knowledge` (Tab «الأقسام/العناصر») بعد مراجعة المحتوى من المختص.
- لا تضف محتوى تخميني (أسعار/ضمانات/توصيات).

## نموذج التسجيل اليدوي

| التاريخ | المستخدم الداخلي | الجمهور المختبر | السؤال | النتيجة | الثقة | المصادر | هل الإجابة كافية؟ | الإجراء التالي |
| ------- | ---------------- | --------------- | ------ | ------- | ----- | ------- | ----------------- | -------------- |
|         |                  |                 |        |         |       |         |                   |                |

قيم عمود «النتيجة» المسموحة:
- `answered`
- `fallback`
- `blocked_sensitive`
- `blocked_internal`
- `needs_human_support`
- `needs_knowledge_update`

## معايير النجاح للأسبوع
1. لا internal leak.
2. لا إجابات مخترعة.
3. fallback داخل النطاق < 10%.
4. الأسئلة الحساسة تبقى blocked أو safe guidance.
5. الدعم يستخدم المسودات بعد مراجعة بشرية فقط.
6. تظهر مصادر لكل إجابة.
7. النواقص مرصودة بوضوح.
8. لا إرسال ولا حفظ تلقائي.

## القيود المعلنة
- لا DB، لا migrations، لا RLS، لا RPC، لا edge functions.
- لا logging زمني — التسجيل يدوي في هذا الملف فقط.
- المساعد يبقى في `releaseLevel = internal_preview` كما هو معرَّف في `src/modules/knowledge/release/knowledgeAssistantReleaseGate.ts`.
